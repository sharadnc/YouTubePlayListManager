Command your YouTube playlists with precision — and spend quota only when something actually changes.

YouTube Playlist Manager (YTPM) is a desktop workspace for owners who maintain large, private, and unlisted playlists. Connect a Google account once, then create, clean, sort, move, and archive lists without fighting YouTube Studio’s limits. On Windows you can unzip a packaged build — no Python on the user PC.

Purpose

YTPM exists because YouTube Studio is slow for bulk playlist work: alphabetical order, duplicate titles after extra spaces, broken rows, renaming videos you uploaded, and moving videos across many lists. The app talks to your channel through the official YouTube Data API. It never needs a second Google Cloud project to “multiply” quota, and it never empties a playlist as a sort strategy.

Every expensive action is designed to be sparse: update a title only if consecutive spaces are still there (or you explicitly rename), delete a row only if it is a duplicate, and rewrite a position only if the item is not already in the right slot. An already-clean, already-sorted playlist costs zero write quota. Sort, Clear, and List Mode Apply can dry-run first (0 write units). The sidebar quota meter is a local ledger — Google does not expose remaining Data API quota.

Install (Windows)

Use a Python venv from this repo, or unzip a packaged folder. Client ID and Secret live in .env. After Connect Google Account, token.json is written next to the app — do not share it.

From source

Set YTPM_VENV in .env. Prefer Run_YTPM.vbs (no CMD window). Missing packages install on startup. CLI: Run_YTPM_CLI.bat.

Packaged zip

Keep YTPM.exe next to _internal. Put Client ID/Secret in .env beside the exe (the exe ignores YTPM_VENV). Double-click, then Connect Google Account. Each person signs in with their own Google account.

Layout on first launch

Playlists and Videos each get 50% of the main pane. Drag the split; closing the app saves window size, split, filters, and last playlist for next time.

Features

Account gate

Connect Google Account on first launch. Token stays local. Reconnect when you switch accounts. TLS uses the OS certificate store on Windows. A second launch focuses the existing window. Source launchers read YTPM_VENV from .env and install missing packages. Packaged YTPM.exe ignores the venv — put .env next to the exe.

Playlist command center

Create, rename, description, privacy, delete, and clear lists. Filter as you type (remembered). Right-click rows. Delete requires a checkbox that the wipe cannot be undone. F2 / Del / Ctrl+F / Enter shortcuts.

Intelligent sort

Sort by Title, Date Added, Duration, or Channel. The sidebar queue shows playlist, key, and pending/done — drop or reorder jobs, then resume after Pacific midnight.

Hygiene

Trim duplicate video ids. Find rows YouTube labeled deleted or inaccessible. Remove selected videos from this playlist without deleting them on YouTube.

List Mode

Export selected playlists to a text file, edit offline, apply the diff when quota allows (or dry-run with 0 writes). Undo picks among the last 20 snapshots.

Library tools

Rename titles on videos you uploaded. Searchable copy/move destination. Each write is logged (id, method, units) next to the local quota meter. First launch: playlists/videos 50/50; your split, window size, and filters are saved on exit.

Notes

  • Selecting a playlist in the left table costs ~2 units the first time (playlistItems.list + videos.list). Switching back uses the local item cache (0 units) until Refresh or a mutation.
  • Column headers (Title, Items, Duration, …) sort the table locally only: 0 units. On startup, Refresh, and after a filter rebuild, Playlists default to Title ▲ and Videos to # ▲. Click another heading to change it until the next rebuild.
  • Multi-select playlists (Ctrl/Shift): Trim, Sort, Clear, Find Broken, Export JSON, Stats, and List Mode Export selected all run on every selected playlist.
  • Sort by Title / Date / Duration / Channel share the same sparse writes:
  • Titles: videos.update only if the title still has extra spaces and you own the video.
  • Duplicates: playlistItems.delete only when a duplicate is found (same video id, or same title after space-collapse). Placeholder titles (Deleted video / Private video) are not merged with each other. Date sort keeps the oldest copy.
  • Order: playlistItems.update only for items that are not already in the right slot. Already-sorted playlists cost 0 write quota.
  • Set Studio Sort → Manual (Open in Studio) before sorting so the app can patch positions in place. Otherwise it spends copy-fallback quota (~2,550 for 50 videos) and does not reorder the original.
  • There is no cheaper official reorder method. 10,000 units/day ÷ 50 = 200 writes. Do not use unofficial YouTube web APIs to dodge quota.
  • Keyboard: F2 rename (playlist or video title, last-clicked table), Del remove selected videos, Ctrl+F focus the videos filter, Enter open the playlist in Studio. Right-click a row for rename, privacy, copy/move, and Studio.
  • Window size, the playlist/videos split, both filter boxes, and the last playlist are remembered in gui_settings.json (saved when you close the app). First launch (or a missing/invalid split): Playlists and Videos each get 50% height. After you drag the divider, the ratio (sash_frac) is restored on the next start. A second Run_YTPM.vbs / YTPM.exe focuses the existing window instead of stacking another.
  • Launch: Prefer Run_YTPM.vbs (no CMD window). It reads YTPM_VENV from .env, runs ytpm_launch.pyw under pythonw, and installs missing packages via ensure_deps (pip uses CREATE_NO_WINDOW). Run_YTPM.bat delegates to the .vbs. CLI/Build still use ytpm_resolve_venv.bat. Packaged YTPM.exe ignores YTPM_VENV — put .env next to the exe. Team zip: Build_YTPM.bat --zip (see docs/distribute.md).
  • CLI (same ops as the GUI): ytpm sort PLAYLIST --by title (or date, duration, channel) with optional --dry-run / --reverse; ytpm sort --resume; ytpm items rename VIDEO_ID "New title"; ytpm playlists description PLAYLIST "Text"; ytpm list export [ids…]; ytpm list apply [--dry-run]; ytpm playlists privacy PLAYLIST public; ytpm stats PLAYLIST; ytpm version. See the CLI section (docs/cli.md).

CLI

Same YouTube Data API v3 operations as the GUI. Prefer Run_YTPM_CLI.bat (reads YTPM_VENV from .env and runs ensure_deps.py first). Or use python -m ytpm from that same venv. Global flag: -v / --verbose (debug logging).

Limitations and YouTube API quota

Google does not sell extra Data API quota. The default allocation is 10,000 units per project per day. HTTP batching does not reduce unit cost. Extra Google Cloud projects used to multiply the 10k cap violate Google’s API terms. A team that shares one Desktop OAuth client (one Cloud project in the Windows zip) also shares that 10,000-unit pool.

You audit the project and ask for more units. Use the official paths below.

What YTPM will not do

  • It cannot switch a playlist to Manual sort via the public API — that is Studio-only.
  • It cannot update titles on videos you do not own. Rename title… uses videos.update and changes the title everywhere, not only in one playlist.
  • It will not delete-and-rebuild a playlist to force order (that can empty the list if quota dies mid-run).
  • Find Broken ignores playable unlisted videos; only YouTube placeholder titles count as broken.
  • The sidebar quota meter is a local estimate. Google does not expose remaining Data API units.
  • The video cache is in-memory only. Refresh drops it. It is not written to disk.
  • Until a quota increase is approved, plan large sorts across days. Dry-run and List Mode save intended order at zero write cost.
